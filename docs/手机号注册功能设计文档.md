# 手机号验证码注册功能设计文档

## 一、功能概述

实现基于手机号+验证码的用户注册功能，包含完整的安全校验、防刷机制和幂等性保证。

## 二、业务流程

### 2.1 整体流程图

```
用户进入注册页
    ↓
输入手机号（前端实时校验格式）
    ↓
输入密码（前端实时校验强度）
    ↓
再次输入密码（前端实时校验一致性）
    ↓
点击"发送验证码"按钮
    ↓
后端校验手机号格式、是否已注册、发送频率
    ↓
生成6位随机验证码
    ↓
存入Redis（10分钟过期）
    ↓
调用短信接口发送
    ↓
前端按钮置灰60秒倒计时
    ↓
用户输入验证码
    ↓
点击"注册"按钮
    ↓
后端校验验证码、密码强度、手机号唯一性
    ↓
加分布式锁
    ↓
BCrypt加密密码
    ↓
写入数据库
    ↓
释放锁、删除验证码
    ↓
注册成功，跳转登录页
```

### 2.2 详细步骤说明

#### 步骤1：前端校验（实时）

**手机号校验**：
- 非空校验
- 格式校验：11位数字，13-19开头
- 正则表达式：`^1[3-9]\d{9}$`

**密码校验**：
- 长度：8-16位
- 必须包含数字和字母
- 禁止纯数字
- 禁止纯字母
- 禁止连续字符（如：123456、abcdef）
- 禁止重复字符（如：111111、aaaaaa）
- 正则表达式：`^(?=.*[0-9])(?=.*[a-zA-Z])(?!.*(.)\1{2,})[0-9a-zA-Z]{8,16}$`

**密码确认**：
- 实时对比两次输入是否一致

#### 步骤2：发送验证码

**前端操作**：
1. 点击按钮后立即置灰
2. 显示60秒倒计时
3. 倒计时结束后恢复可点击状态

**后端校验**：
1. 手机号格式校验（兜底）
2. 查询数据库，检查手机号是否已注册
3. 检查Redis中该手机号上次发送时间，间隔必须≥60秒
4. 检查Redis中该手机号当日发送次数，必须<5次
5. 检查Redis中该IP当日发送次数，必须<20次

**验证码生成**：
- 生成6位随机数字
- 不允许连续数字（如：123456）
- 不允许重复数字（如：111111）
- 算法：随机生成后校验，不符合则重新生成

**Redis存储结构**：
```
Key: verify_code:{phone}
Value: Hash结构
{
  "code": "123456",           // 验证码
  "sendTime": 1702345678901,  // 发送时间戳
  "dailyCount": 3,            // 当日发送次数
  "retryCount": 0,            // 错误重试次数
  "verified": false           // 是否已验证
}
TTL: 600秒（10分钟）
```

**短信发送**：
- 调用第三方短信接口
- 发送成功：记录日志
- 发送失败：删除Redis中的验证码，返回错误信息

#### 步骤3：验证码校验

**校验逻辑**：
1. 从Redis获取验证码数据
2. 检查验证码是否存在（未过期）
3. 检查错误重试次数是否<3次
4. 对比用户输入与存储的验证码
5. 验证成功：标记`verified=true`
6. 验证失败：累加`retryCount`，超过3次需重新获取

#### 步骤4：注册

**前端操作**：
- 生成唯一请求ID（UUID）
- 携带请求ID发起注册请求

**后端校验**：
1. **幂等性校验**：检查请求ID是否已处理
   ```
   Key: request_idempotent:{requestId}
   Value: "PROCESSING" | "SUCCESS" | "FAILED"
   TTL: 300秒（5分钟）
   ```

2. **加分布式锁**：以手机号为Key加锁，防止并发注册
   ```
   Key: register_lock:{phone}
   TTL: 30秒
   ```

3. **二次校验**：
   - 手机号格式
   - 手机号唯一性（数据库查询）
   - 验证码有效性（Redis中verified=true）
   - 密码强度（兜底）

4. **密码加密**：
   ```java
   String encryptedPassword = BCryptPasswordEncoder.encode(password);
   ```

5. **写入数据库**：
   ```sql
   INSERT INTO sys_user (
     username, phone, password, user_type, status,
     register_source, register_ip, is_phone_verified,
     create_time, update_time
   ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, NOW(), NOW())
   ```

6. **清理数据**：
   - 释放分布式锁
   - 删除Redis中的验证码
   - 标记请求ID为SUCCESS

7. **返回结果**：
   - 注册成功，返回用户信息
   - 前端跳转登录页

## 三、数据库设计

### 3.1 用户表修改

```sql
ALTER TABLE sys_user
    -- 手机号必填且唯一
    MODIFY COLUMN phone VARCHAR(20) NOT NULL COMMENT '手机号（必填）',
    ADD UNIQUE INDEX uk_phone (phone),

    -- 注册相关字段
    ADD COLUMN register_source VARCHAR(20) DEFAULT 'WEB',
    ADD COLUMN register_ip VARCHAR(50),
    ADD COLUMN is_phone_verified TINYINT DEFAULT 1;
```

### 3.2 验证码日志表

```sql
CREATE TABLE sms_verify_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    phone VARCHAR(20) NOT NULL,
    verify_code VARCHAR(10) NOT NULL,
    code_type VARCHAR(20) NOT NULL,
    send_status TINYINT NOT NULL DEFAULT 1,
    is_verified TINYINT DEFAULT 0,
    verify_time DATETIME,
    ip_address VARCHAR(50),
    expire_time DATETIME NOT NULL,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 3.3 请求幂等性表

```sql
CREATE TABLE request_idempotent (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    request_id VARCHAR(64) NOT NULL UNIQUE,
    request_type VARCHAR(50) NOT NULL,
    status TINYINT NOT NULL DEFAULT 0,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    expire_time DATETIME NOT NULL
);
```

## 四、Redis数据结构

### 4.1 验证码数据

```
Key: verify_code:{phone}
Type: Hash
Fields:
  - code: 验证码
  - sendTime: 发送时间戳
  - dailyCount: 当日发送次数
  - retryCount: 错误重试次数
  - verified: 是否已验证
TTL: 600秒
```

### 4.2 发送次数限制

```
Key: verify_code_count:{phone}:{date}
Type: String
Value: 发送次数
TTL: 86400秒（24小时）
```

### 4.3 IP发送限制

```
Key: verify_code_ip:{ip}:{date}
Type: String
Value: 发送次数
TTL: 86400秒（24小时）
```

### 4.4 请求幂等性

```
Key: request_idempotent:{requestId}
Type: String
Value: PROCESSING | SUCCESS | FAILED
TTL: 300秒
```

### 4.5 分布式锁

```
Key: register_lock:{phone}
Type: String
Value: 锁标识
TTL: 30秒
```

## 七、安全机制

### 7.1 防刷机制

1. **60秒发送间隔**：同一手机号60秒内只能发送一次
2. **每日5次限制**：同一手机号每天最多发送5次
3. **IP限制**：同一IP每天最多发送20次
4. **错误重试限制**：验证码错误3次后需重新获取

### 7.2 并发控制

1. **分布式锁**：注册时以手机号为Key加锁
2. **请求幂等性**：使用请求ID防止重复提交
3. **数据库唯一索引**：phone字段唯一约束

### 7.3 数据安全

1. **密码加密**：BCrypt自动加盐加密
2. **验证码加密存储**：Redis中存储时可选加密
3. **敏感信息脱敏**：日志中手机号脱敏显示

## 八、定时任务

### 8.1 验证码清理

**执行时间**：每天凌晨2点

- 清理请求幂等性记录（保留7天）
